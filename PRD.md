# Project Requirements Document (PRD): Phase 2B, Privacy and encryption

## Overview
Multi-school, multi-campus School ERP for Pakistani schools. Step 1 (schema) and Phase 2A (Access module) are DONE. This PRD covers **Phase 2B only**: encrypted identifiers with blind indexes, encrypted medical and custody details, the PII viewer with audit, and the key runbook. Do NOT start 2C (fees and ledger) or 2D (academic engine). The Phase 2A PRD is archived at `school-erp/docs/archive/PRD_phase2a.md`.

## Stack and environment (fixed)
- Laravel 12, PHP 8.2+, PostgreSQL 16 (native), Pest, Pint, Larastan level 5. Credentials and keys come from `.env`; never hardcode or commit them.
- Source of truth: `school-erp/docs/DECISIONS_PHASE2.md` sections B (D-23 to D-27) and F (D-32 to D-36). Read them first. Anything not decided there: stop and ask.
- Existing services to reuse: `App\Services\Access\AccessResolver`, `ScopeContext`, the `AuditLog` model.

## Hard rules (apply to every task)
1. Migrations `2026_10_02_000001..000012` and `2026_10_06_000001` are FROZEN. The only new migrations allowed are the two provided: `2026_10_07_000001_add_privacy_columns.php` and `2026_10_07_000002_create_student_medical_and_custody_tables.php` (already verified, do not edit). Any other schema change: stop, write it under `BLOCKED` in `progress.txt`, wait for the user.
2. Do not invent tables, columns, permissions or rules. Not in `DECISIONS_PHASE2.md` means not decided.
3. `php artisan migrate:fresh --seed` must rebuild everything, and running seeders twice must change nothing.
4. Never write plaintext PII (CNIC, B-Form, passport, medical text, custody text) to logs, exception messages, audit rows, test names or `progress.txt`. Test data must be obviously fake.
5. Never decrypt to search. Lookups use the blind-index hash only.
6. Tenant safety: every query on tenant data filters by `organization_id`.
7. Never weaken or delete an existing test. If one fails, report it.
8. One task per turn. Verify, log to `progress.txt`, then STOP. Never run git add, git commit or git push; the user commits.
9. Verification gate for every PHP task: `php -l` on changed files, `./vendor/bin/pint --test`, `./vendor/bin/pest`, `./vendor/bin/phpstan analyse`. All must pass.
10. Do not build routes, controllers or any HTTP endpoint in this PRD.

## Tasks
- [x] Task 1: Blind index service and key config. Create `config/privacy.php` (`blind_index_key` from `env('BLIND_INDEX_KEY')`), add a placeholder line to `.env.example`, and add a fixed test-only key to `phpunit.xml`. Create `App\Services\Privacy\BlindIndex` with `normalize(string $v): string` and `hash(string $organizationId, ?string $value): ?string` implementing D-26 and D-35: `hash_hmac('sha256', $organizationId . '|' . $normalized, $key)`, lowercase hex, null when the value is null or empty after normalizing. Outside the testing environment a missing or short (< 32 chars) key throws a clear exception on first use. Tests (Unit): dashes and spaces give the same hash (`12345-1234567-1` equals `1234512345671`); case does not matter for passports; same value in two organizations gives different hashes; a different key gives a different hash; output is 64 lowercase hex chars; null and empty give null; short or missing key throws (non-testing simulation). Done when: the gate passes.
- [ ] Task 2: Install the privacy migrations. Copy the two provided migration files into `database/migrations/`. Remove the `medical` entry from the casts in `app/Models/Student.php` (and from fillable if present). Run `php artisan migrate:fresh --seed`. Add `tests/Feature/PrivacyConstraintsTest.php`: duplicate `b_form_hash` in the same organization is rejected; same hash in another organization is allowed; many NULL hashes are allowed; a soft-deleted student frees the hash; the same for `passport_hash`; a malformed hash (uppercase, too short) is rejected; guardian and employee duplicate `national_id_hash` are allowed; second medical profile for one student is rejected; medical profile and custody order for a student of another organization are rejected; `students.medical` no longer exists; `has_medical_alert` and `has_severe_allergy` default to false. Done when: the gate passes.
- [ ] Task 3: Encrypted models. Update `Student`, `Guardian`, `Employee`; create `StudentMedicalProfile` and `StudentCustodyOrder` (ULIDs, relations, `organization_id` scoping). Use Laravel's `encrypted` cast for: `students.b_form_encrypted`, `students.passport_encrypted`, `guardians.national_id_encrypted`, `employees.national_id_encrypted`, the four medical columns, and custody `details`. Add `$hidden` for every ciphertext and hash column (D-36). Add helpers that set the encrypted value and its hash together through `BlindIndex`: `Student::setBForm(?string)`, `Student::setPassport(?string)`, `Guardian::setNationalId(?string)`, `Employee::setNationalId(?string)`; passing null clears both columns. Add query scopes that look up by hash only: `Student::whereBForm()`, `Student::wherePassport()`, `Guardian::whereNationalId()`, `Employee::whereNationalId()` (they take the organization id and the plain value). Tests: the raw database column never equals the plain value and is not readable as plain text; the round trip returns the plain value; lookup by differently formatted CNIC finds the same row; the same value in another organization is not found; `toArray()` and `toJson()` contain no ciphertext or hash key; setting null clears both columns. Done when: the gate passes.
- [ ] Task 4: PII viewer. Create `App\Services\Privacy\PiiViewer` and `PiiAccessDenied`. Methods return plain text only after `AccessResolver::can()` passes with the caller's `ScopeContext`, using the table in D-33: `studentIds(User, Student, ScopeContext)` (b_form and passport), `guardianNationalId(User, Guardian, ScopeContext)`, `employeeNationalId(User, Employee, ScopeContext)`, `medical(User, StudentMedicalProfile, ScopeContext)`, `custody(User, StudentCustodyOrder, ScopeContext)`. On success write one `audit_logs` row: action `pii.viewed`, `actor_id`, `organization_id`, `subject_type`, `subject_id`, meta `{field_group}` (never the value). On denial throw `PiiAccessDenied` and write no `pii.viewed` row. Tests: allowed user gets the value and exactly one audit row; user without the permission is denied and no row is written; a user from another organization is denied; the audit meta contains no plain value; campus-scoped holder denied for another campus. Done when: the gate passes.
- [ ] Task 5: Medical profile service. Create `App\Services\Privacy\StudentMedicalService::save(User $actor, Student $student, array $data, ScopeContext $scope, bool $severeAllergy = false): StudentMedicalProfile`. Needs `pastoral.medical.edit` (else `PiiAccessDenied`). In one DB transaction: upsert the profile (one per student), set `has_medical_alert` true when any of allergies, conditions or medications is non-empty else false (D-34), set `has_severe_allergy` from the argument, write an `audit_logs` row `pii.updated` with field group `medical` only. Tests: first save creates the profile and sets the flags; clearing the details turns `has_medical_alert` off; `has_severe_allergy` follows the argument; permission missing means nothing is written; a second save updates the same row; audit row contains no values; the stored columns are ciphertext. Done when: the gate passes.
- [ ] Task 6: Key runbook. Write `school-erp/docs/runbooks/KEYS_AND_BACKUPS.md` from D-27 and D-35: which secrets exist (`APP_KEY`, `BLIND_INDEX_KEY`), where they live (secrets store, never in the repo or in the database backup bucket), how to generate a blind index key, how to rotate `APP_KEY` with `APP_PREVIOUS_KEYS`, what rotating `BLIND_INDEX_KEY` means (every hash must be recomputed; needs a planned command, not built now), and the warning that losing a key loses the data.
