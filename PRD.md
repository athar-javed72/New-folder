# Project Requirements Document (PRD): Phase 2A, Access module

## Overview
Multi-school, multi-campus School ERP for Pakistani schools. Step 1 (schema, presets, golden tests) is DONE and pushed. This PRD covers **Phase 2A only**: the Access module (permission catalog, system roles, resolver, delegation, separation of duties, password hashing config). Do NOT start 2B (privacy and encryption), 2C (fees and ledger) or 2D (academic engine).

## Stack and environment (fixed)
- Laravel 12, PHP 8.2+, PostgreSQL 16 (native, not Docker), Pest, Pint, Larastan level 5. Credentials come from `.env`; never hardcode or commit them.
- Project: `./school-erp/`. The Step 1 PRD is archived at `school-erp/docs/archive/PRD_step1.md`.
- Source of truth for every decision: `school-erp/docs/DECISIONS_PHASE2.md` (section A, D-19 to D-22). Read it first. Also read `school-erp/docs/DOCUMENTATION_PACKAGE.md` (D-01 to D-18).
- Data source: `school-erp/database/data/access_matrix.json` (generated from D-21; do not hand-edit its meaning, and do not add permissions that are not in D-21).

## Hard rules (apply to every task)
1. Migrations `2026_10_02_000001..000012` are FROZEN. The only new migration allowed in this PRD is `2026_10_06_000001_create_sod_rules_table.php` (already provided, already verified). Any other schema change: stop, write it under `BLOCKED` in `progress.txt`, wait for the user.
2. Do not invent permissions, roles, tables, columns or business rules. Not in `DECISIONS_PHASE2.md` or `access_matrix.json` means not decided: stop and ask.
3. `php artisan migrate:fresh --seed` must rebuild everything from nothing, and running the seeders twice must change nothing.
4. Tenant safety: every query on tenant data filters by `organization_id`. System roles have `organization_id` NULL.
5. Sensitive permissions (`is_sensitive`) can only be granted by the Org Admin. Never set `with_grant` on a sensitive row in the matrix.
6. Never weaken or delete an existing test. If one fails, report it.
7. One task per turn. Verify, log to progress.txt, then STOP. Never run git add, git commit or git push; the user commits.
8. Verification gate for every PHP task: `php -l` on changed files, `./vendor/bin/pint --test`, `./vendor/bin/pest`, `./vendor/bin/phpstan analyse` (Larastan level 5). All must pass before commit.
9. Do not build login, register or any HTTP endpoint in this PRD. API contracts are written first (separate doc).

## Scope mapping used by the matrix (decided)
Matrix scopes: `org`, `campus`, `assigned`, `self`. Stored in `role_permissions.max_scope` as: org -> `org`, campus -> `campus`, assigned -> `section`, self -> `section`. The resolver narrows `assigned` to the user's assigned classes, sections and subjects, and `self` to the user's own record or own children (via `guardian_student`). Do not change the `max_scope` CHECK.

Rules: `users.is_super_admin` passes; otherwise union of permissions from active `role_assignments` (status `active`, now between `starts_at` and `ends_at`, same organization) and active `permission_grants`; a holder at a wider scope covers a narrower one (org > campus > program > grade > section > session); the role's `max_scope` is a ceiling; suspended, revoked or expired rows never count; a permission whose module is disabled in `module_enablement` is denied. Tests (Feature): campus admin of campus A cannot act on campus B; expired assignment denied; `assigned` scope only for assigned section; super admin passes; cross-organization denied.
