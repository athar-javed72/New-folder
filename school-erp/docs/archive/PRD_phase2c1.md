# Project Requirements Document (PRD): Phase 2C-1, Ledger core

## Overview
Multi-school, multi-campus School ERP for Pakistani schools. Step 1 (schema), Phase 2A (Access) and Phase 2B (Privacy) are DONE. This PRD covers **Phase 2C-1 only**: the accounting engine that fees and payments will post into (chart of accounts, ledger periods, journal entries and lines, gap-free number sequences, a posting service with reversals, trial balance and family balance reports). It moves no money by itself. Do NOT start 2C-2 (fee setup and vouchers), 2C-3 (payments), 2C-4 (discounts and refunds) or 2D. The Phase 2B PRD is archived at `school-erp/docs/archive/PRD_phase2b.md`.

## Stack and environment (fixed)
- Laravel 12, PHP 8.2+, PostgreSQL 16 (native), Pest, Pint, Larastan level 5. Credentials and keys come from `.env`; never hardcode or commit them.
- Source of truth: `school-erp/docs/DECISIONS_PHASE2.md`, sections C (D-28 to D-30) and H (D-44 to D-52). Read them first. Anything not decided there: stop and ask.
- Existing code to reuse: `App\Services\Access\AccessResolver`, `ScopeContext`, the `AuditLog` model, the `MorphMapServiceProvider`, `tests/Support/DbFactory.php`, the pattern of `App\Services\Privacy\PiiViewer` (organization check first, then permission, generic denial exception).

## Hard rules (apply to every task)
1. Migrations `2026_10_02_000001..000012`, `2026_10_06_000001` and `2026_10_07_*` are FROZEN. The only new migration allowed is the provided `2026_10_08_000001_create_ledger_core_tables.php` (already verified against PostgreSQL 16, do not edit). Any other schema change: stop, write it under `BLOCKED` in `progress.txt`, wait for the user.
2. Do not invent tables, columns, permissions or rules. Not in `DECISIONS_PHASE2.md` means not decided. No new permission codes.
3. `php artisan migrate:fresh --seed` must rebuild everything, and running seeders twice must change nothing.
4. Money is `bigint` paisa. No floats, no decimals, no `round()` anywhere in ledger code.
5. Ledger rows are never updated or deleted by any code path. Corrections are reversals.
6. Never compute a number with `max()+1`. Numbers come only from `NumberSequenceService::next()`.
7. Tenant safety: every query on tenant data filters by `organization_id`.
8. Never write PII to logs, exception messages, audit rows, memos or test names. Test data must be obviously fake.
9. Never weaken or delete an existing test. If one fails, report it.
10. One task per turn. Verify, log to `progress.txt` (append only, never rewrite earlier entries), then STOP. Never run git add, git commit or git push; the user commits.
11. Verification gate for every PHP task: `php -l` on changed files, `./vendor/bin/pint --test`, `./vendor/bin/pest`, `./vendor/bin/phpstan analyse`. All must pass.
12. Do not build routes, controllers or any HTTP endpoint in this PRD.

## Testing notes (read before writing tests)
- Feature tests run inside the RefreshDatabase transaction, and a failed SQL statement aborts that transaction. Wrap every statement that is expected to fail in a nested `DB::transaction(...)` (it uses a savepoint), as the existing constraint tests do, and assert the `QueryException`.
- The balance trigger is DEFERRED, so it only fires at COMMIT, which never happens inside RefreshDatabase. In constraint tests that insert raw rows, end the nested transaction closure with `DB::statement('SET CONSTRAINTS journal_entries_balanced, journal_lines_balanced IMMEDIATE')` to force the check. The poster does this itself (D-46).
- Use obviously fake ids and names. Amounts in tests are paisa.
